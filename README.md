## Angular Project - Functional Guide

1.	Application Purpose

The goal of the application is to help each user find the most suitable partner based on their personality traits and interests.

2.	User Roles

### Guest (Not Authenticated User)
- Can register.
- Can log in.
### Authenticated User
- Can edit their profile information.
- Can add additional interests and hobbies.
- Can answer personality questions to generate suitable matches.
- Can search for users based on specific criteria.
- Can upload and delete their own photos.
- Can react to their own photos as well as photos of other users (likes and comments).
- Can discover matches for themselves based on their answers generated by the application.
- Can approve matches with the intention of starting communication/chat.
- Can reject matches, and later, in the rejected matches list, choose to permanently delete the generated match or restore it to mutual matches.
- Can send messages

3.	Public Features

## Pages and Features

### Public Pages
- **Landing page (`/`)** – Displays the main interface with app logo and links to register or log in.
- **Login page** – Allows users to log in to their account.
- **Registration page** – Allows new users to create an account.

### Authenticated User Features
- **Editing their own records** – Users can update personal profile information.
- **Filling in hobbies and interests** – Users provide hobbies and dating preferences.
- **Answering personality questions** – Helps generate compatible matches.
- **Uploading and deleting their own photos** – Manage personal photo gallery.
- **Viewing personal dashboard** – Overview of profile, matches, and activity.
- **Reacting to other users’ photos (likes and comments)** – Interact with other users’ photos.
- **Searching for other users based on specific criteria** – Filter by age, location, interests, etc.
- **Discovering, approving, or deleting generated matches** – Manage compatibility matches.
- **Viewing the profiles of discovered matches** – See full profile details including bio, photos, and interests.
- **Sending messages**– Users can send messages to their matches.

4.	Main Application Flow

1.	The user opens the Landing page.
2.	The user logs in or registers.
3.	After logging in, the user accesses the Home page. (From this page, they will have access to all the buttons and functionalities listed below, including information about their compatible zodiac signs.)
4.	The authenticated user edits their profile records.
5.	The authenticated user fills in their interests and hobbies.
6.	The authenticated user answers personality questions.
7.	The authenticated user uploads and deletes their own photos and can view their entire profile as a combination of bio, interests, and photos.
8.	The authenticated user searches for other users based on specific criteria and views their profiles accordingly.
9.	The authenticated user can like and comment on both their own photos and the photos of other users.
10.	 The authenticated user accesses the matches generated for them by the application, along with the percentage of compatibility. (The matches are generated based on users’ answers and their age difference, and only matches with over 50% compatibility are considered.
11.	 The authenticated user can approve matches found for them, which then become mutual (if approved by the other profile as well).
12.	 The authenticated user can reject matches, which are then moved to an appropriate “rejected matches” list.
13.	 The authenticated user, after navigating to the rejected matches list, can either restore matches or permanently delete them.
14.	 The authenticated user can send messages to their matches(mutual matches).

5.	Data Structure 

## Main Data Objects

### 1. User Profile Object
**Description:** Represents a registered user and stores all their profile information, used for matchmaking.

**Sections / Key Fields:**

- **Profile**  
  **Description:** Basic info for user  
  **Contains:** objects with the following fields:  
  - `id`  
  - `username`  
  - `firstName`  
  - `age`  
  - `town`  
  - `gender`  
  - `profilePicture`  
  - `createdOn`  
  - `updatedOn`  

- **Hobbies and Interests**  
  **Description:** User’s hobbies and interests (Dating Profile)  
  **Contains:**  
  - `id`  
  - `bio`  
  - `hobbies` (e.g., swimming, cooking, music)  
  - `relationshipStatus`  
  - `relationshipType`  
  - `childrenStatus`  
  - `wantsChildren`  

- **Personality Questions**  
  **Description:** Answers used for generating compatible matches (Personality)  
  **Contains:**  
  - `id`  
  - `smokingHabit`  
  - `alcoholConsumption`  
  - `likesAnimals`  
  - `hasPets`  
  - `wantsPets`  
  - `zodiacSign`  
  - `cheatingDefinition`  
  - `cheatingForgiveness`  
  - `conflictResolutionStyle`  
  - `partnerIndependenceLevel`  
  - `relationshipSecretsPolicy`  
  - `relationshipPriority`  
  - `hurtResponseExpectation`  
  - `apologyMethod`  
  - `relationshipRoles`  

- **Photos**  
  **Description:** Uploaded photos of the user  

---

### 2. Matches Object
**Description:** Stores generated matches for each user, categorized by status.

**Collections / Key Fields:**

- **Generated Matches**  
  **Description:** Collection of matches suggested by the application based on personality answers and age difference (only over 50% compatibility)  
  **Contains:** objects with the following fields:  
  - `id`  
  - `personalityScore`  
  - `hobbiesScore`  
  - `overallScore`  
  - `matchedOn`  
  - `userA`  
  - `userB`  
  - `matchStatus`  
  - `userAApproved`  
  - `userBApproved`  
  - `userARejected`  
  - `userBRejected`  

- **Mutual Matches**  
  **Description:** Collection of matches approved by both users  
  **Contains:** objects with the following fields:  
  - `matchId` – unique identifier of the match  
  - `userId` – ID of the matched user (the other user in the match)  
  - `username` – matched user's username  
  - `photoUrl` – matched user's profile picture  
  - `overallScore` – compatibility score for the match  
  - `matchedOn` – date when the match was generated  

- **Rejected Matches**  
  **Description:** Collection of matches rejected by the user, can later be restored or permanently deleted  
  **Contains:** objects with the following fields:  
  - `matchId` – unique identifier of the match  
  - `userId` – ID of the other user in the match  
  - `username` – other user's username  
  - `photoUrl` – other user's profile picture  
  - `overallScore` – compatibility score for the match  
  - `matchStatus` – status of the match (e.g., "rejected")  
  - `matchedOn` – date when the match was generated  

---

### 3. Photos Object
**Description:** Stores all photos uploaded by users  

**Contains:**  
- `id` – unique identifier of the photo  
- `description`  
- `uploadedAt`  
- `user` – owner of the photo  
- `url` / `file` – link or file path to the photo  
- `reactions` – references to reactions (likes/comments) on this photo  

---

### 4. Reactions Object
**Description:** Stores user interactions with photos, including likes and comments.  

**Contains:**  
- `id` – identifier of the photo being reacted to  
- `photoId` – identifier of the photo  
- `likedUser` or `commentedUser` (profiles)  
- `commentedAt`  
- `content` – text of the comment (only for comments)  

---

### 5. Chat Object
**Description:** Messaging between users who have an approved match.  

**Contains:**  
- `id` – Unique identifier of the message
- `chatRoomId` – Identifier of the chat room/conversation the message belongs to
- `senderId` – Unique identifier of the user who sent the message
- `senderUsername`  – Username of the sender, for displaying in the UI
- `content` – The actual content of the message (the text sent)
- `sentAt` – Date of sending
- `isMine` – Boolean indicating whether the message was sent by the current user (true) or someone else (false)

8.	How to Run the Project

Provide instructions for running the project locally.

### 1. Clone the repository
Open the entire project in IntelliJ IDEA (root folder).

### 2. Backend:
-    Install and start MySQL server
Download MySQL from: https://dev.mysql.com/downloads/

-    Create a database (optional, it will be created automatically): `matchly_db`

-	Open the backend folder (matchly-backend)
-	Run the main application class (MatchlyApplication)
-	The backend will start on:  http://localhost:8080

> **Note:** The application uses a MySQL database.
> Make sure MySQL is running locally before starting the backend.

> **Configuration:**
> Update the following properties in `application.properties`:
> - `spring.datasource.username`
> - `spring.datasource.password`

### 3. Frontend:
-	Open a terminal in the frontend folder (matchly-app-frontend)
-	Install dependencies:
npm install
-	Start the application:
ng serve
-	Open the application –  http://localhost:4200
